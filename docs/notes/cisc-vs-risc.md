# CISC と RISC アーキテクチャの比較

## 1. 基本概念

### 1.1 CISC (Complex Instruction Set Computer)

**定義**: 複雑命令セットコンピュータ。単一の命令で複雑な操作を実行できるアーキテクチャ。

**設計思想**:

- **セマンティックギャップの削減**: 高級言語の操作を直接的にハードウェア命令にマッピング
- **メモリ効率の重視**: プログラムサイズを小さくすることで、高価だったメモリを節約
- **マイクロプログラム制御**: 複雑な命令をマイクロコードで実装

### 1.2 RISC (Reduced Instruction Set Computer)

**定義**: 縮小命令セットコンピュータ。シンプルで固定長の命令セットを持つアーキテクチャ。

**設計思想**:

- **単純性の原則**: 各命令は 1 クロックサイクルで実行可能な単純な操作
- **コンパイラ最適化**: ハードウェアの複雑性をソフトウェア（コンパイラ）に移譲
- **パイプライン処理の効率化**: 固定長命令による予測可能な実行

## 2. アーキテクチャの特徴比較

| 特徴                     | CISC                           | RISC                           |
| ------------------------ | ------------------------------ | ------------------------------ |
| **命令数**               | 多い（100 ～ 1000 以上）       | 少ない（50 ～ 100 程度）       |
| **命令長**               | 可変長（1 ～ 15 バイト）       | 固定長（通常 32 ビット）       |
| **命令の複雑度**         | 複雑（マルチサイクル実行）     | 単純（単一サイクル実行）       |
| **アドレッシングモード** | 多様（10 ～ 20 種類）          | 限定的（3 ～ 5 種類）          |
| **レジスタ数**           | 少ない（8 ～ 16 個）           | 多い（32 個以上）              |
| **メモリアクセス**       | 多くの命令でメモリアクセス可能 | Load/Store 命令のみ            |
| **制御方式**             | マイクロプログラム制御         | ハードワイヤード制御           |
| **パイプライン**         | 複雑、深いパイプライン         | シンプル、効率的なパイプライン |

## 3. 命令セットの違い

### 3.1 CISC の命令例（x86）

```assembly
; 複雑な単一命令でのメモリ間演算
ADD [mem1], [mem2]  ; メモリ位置mem1に mem2の値を加算

; 文字列操作専用命令
REP MOVSB           ; 文字列のコピー（繰り返し付き）

; スタック操作と関数呼び出し
ENTER 16, 0         ; スタックフレームの作成
LEAVE               ; スタックフレームの破棄
```

### 3.2 RISC の命令例（RISC-V）

```assembly
# メモリ間演算は複数命令に分解
lw   t0, 0(a0)      # mem1をレジスタt0にロード
lw   t1, 0(a1)      # mem2をレジスタt1にロード
add  t0, t0, t1     # レジスタ間で加算
sw   t0, 0(a0)      # 結果をmem1に格納

# 文字列操作は基本命令の組み合わせ
loop:
    lb   t0, 0(a0)   # 1バイトロード
    sb   t0, 0(a1)   # 1バイトストア
    addi a0, a0, 1   # ポインタ更新
    addi a1, a1, 1   # ポインタ更新
    bnez t0, loop    # 条件分岐
```

## 4. RISC-V による RISC の実装例

### 4.1 RISC 設計原則の体現

RISC-V は @docs/notes/riscv-overview.md で説明されているように、RISC の設計原則を純粋に実装しています：

#### レジスタ-レジスタアーキテクチャ

```
演算命令はレジスタ間でのみ実行：
- add  rd, rs1, rs2  # rd = rs1 + rs2
- sub  rd, rs1, rs2  # rd = rs1 - rs2
- and  rd, rs1, rs2  # rd = rs1 & rs2
```

#### Load/Store アーキテクチャ

```
メモリアクセスは専用命令のみ：
- lw   rd, offset(rs1)  # Load Word
- sw   rs2, offset(rs1) # Store Word
```

#### 固定長命令（32 ビット）

```
全ての基本命令は32ビット固定：
┌─────┬─────┬─────┬─────┬─────┬─────┬─────┐
│funct7│ rs2 │ rs1 │funct3│ rd │opcode│
└─────┴─────┴─────┴─────┴─────┴─────┴─────┘
  7bits  5bits 5bits 3bits 5bits 7bits = 32bits
```

### 4.2 RISC-V のモジュラー設計

RISC-V は基本 ISA（RV32I/RV64I）に拡張を追加する形式：

```
RV32I: 基本32ビット整数命令セット（47命令）
├── 算術論理演算: 10命令
├── Load/Store: 8命令
├── 分岐: 6命令
├── Jump: 2命令
├── システム: 8命令
└── その他: 13命令

標準拡張:
M: 乗除算（8命令追加）
A: アトミック操作（11命令追加）
F: 単精度浮動小数点（26命令追加）
D: 倍精度浮動小数点（26命令追加）
C: 圧縮命令（16ビット命令形式）
```

## 5. パフォーマンスの観点

### 5.1 実行効率

#### CISC の場合

```
複雑な命令 → マイクロコード展開 → 複数マイクロ命令実行
例: x86 の REP MOVSB
    ↓
内部で数十のマイクロ命令に展開
実行に数十～数百サイクル
```

#### RISC の場合

```
単純な命令 → 直接実行
例: RISC-V の add 命令
    ↓
1サイクルで実行完了（理想的な場合）
```

### 5.2 パイプライン効率

#### RISC-V の 5 段パイプライン

```
IF → ID → EX → MEM → WB
│    │    │     │     │
取得 解読 実行  メモリ 書戻し

固定長命令により：
- 命令取得が単純（常に4バイト）
- デコードが高速（固定フィールド）
- ハザード検出が容易
```

#### CISC（x86）のパイプライン

```
可変長命令により：
- 命令境界の検出が複雑
- プリデコードステージが必要
- 分岐予測が困難
```

## 6. 現代のプロセッサにおける収束

### 6.1 CISC プロセッサの内部 RISC 化

現代の x86 プロセッサ（Intel Core、AMD Ryzen）：

```
CISC命令 → デコーダ → マイクロ命令（μops） → RISCライクな実行エンジン
         ↑                    ↓
    複雑な変換          内部的にはRISC的処理
```

### 6.2 RISC プロセッサの機能拡張

ARM や RISC-V も実用性のため複雑な機能を追加：

- **SIMD 命令**: ベクトル処理
- **暗号化命令**: AES、SHA 等の専用命令
- **アトミック命令**: マルチコア対応
- **圧縮命令**: コードサイズ削減（RISC-V の C 拡張）

## 7. 用途別の適性

### 7.1 CISC が有利な場面

1. **後方互換性が重要**: x86 の 40 年以上の資産
2. **レガシーソフトウェア**: 既存バイナリの実行
3. **手書きアセンブリ**: 複雑な命令による最適化

### 7.2 RISC が有利な場面

1. **組み込みシステム**: シンプルな実装、低消費電力
2. **教育・研究**: 理解しやすいアーキテクチャ
3. **カスタムプロセッサ**: 特定用途向け最適化
4. **新規設計**: ライセンスコスト削減（RISC-V）

## 8. RISC-V が示す未来

### 8.1 オープンソース ISA の意義

RISC-V は単なる RISC 実装を超えた意味を持ちます：

```
従来のプロセッサ開発:
企業 → プロプライエタリISA → ライセンス料 → 製品

RISC-Vによる新しいモデル:
コミュニティ → オープンISA → 自由な実装 → イノベーション
```

### 8.2 カスタマイズ可能な RISC

RISC-V のモジュラー設計により：

- **基本 ISA**: 最小限の命令セット
- **標準拡張**: 必要な機能のみ追加
- **カスタム拡張**: 独自の最適化

例：IoT デバイス向け最小構成

```
RV32I + C拡張 = 超小型・低消費電力プロセッサ
（約50命令、16ビット圧縮命令対応）
```

例：AI アクセラレータ

```
RV64GCV + カスタムベクトル拡張 = 高性能AI処理
（汎用計算 + SIMD + 独自の行列演算）
```

## 9. まとめ

### CISC と RISC の本質的な違い

**CISC**: ハードウェアで複雑性を吸収

- 利点：高密度コード、強力な単一命令
- 欠点：実装の複雑化、最適化の困難

**RISC**: ソフトウェア（コンパイラ）で複雑性を管理

- 利点：シンプルな実装、効率的なパイプライン
- 欠点：コードサイズ増大、コンパイラ依存

### 現代における境界の曖昧化

技術の進化により、純粋な CISC や RISC は存在せず：

- CISC は内部で RISC 化
- RISC は実用的な複雑命令を追加

### RISC-V の位置づけ

RISC-V は「第 5 世代 RISC」として：

1. **純粋な RISC 原則の継承**: シンプルで正規直交的な命令セット
2. **現代的な拡張性**: モジュラー設計による柔軟性
3. **オープンエコシステム**: イノベーションの加速

RISC-V は RISC の理想を現代的に再解釈し、オープンソースの理念と組み合わせることで、次世代のコンピュータアーキテクチャの標準となる可能性を秘めています。
